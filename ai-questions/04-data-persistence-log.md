### Q1

**質問：**
（生成AIに聞いた質問をそのまま書く）

なぜ Memo は class で定義されているのですか？struct ではだめなのですか？

**AIの回答の要点：**
（長い回答の場合、要点だけ自分の言葉でまとめる）

SwiftData の @Model はデータの変更を追跡するために参照型（class）を使う。

class にすることで同じデータを複数の画面で共有でき、変更が自動的に反映される。

struct は値型なのでコピーが発生し、データの一貫性を保ちにくい。

**自分の理解：**
（回答を受けて自分がどう理解したか。納得できたか、さらに疑問が生まれたか）

struct は「コピーされたプリント紙」のようなもので、書き換えても元には影響しない。

class は「みんなで共有するノート」で、誰かが書き換えると全員に反映される。

SwiftData はデータの変化を反映する必要があるので class を使うと理解した。

### Q2

**質問：**

なぜメモは SwiftData で保存し、ユーザー名は AppStorage で保存しているのですか？

**AIの回答の要点：**

SwiftData は、メモのような「複数・構造化されたデータ」を管理・保存するための仕組みである。

AppStorage は、ユーザー名や設定のような「少量でシンプルな値」を保存するための仕組みである。

データの性質に応じて保存方法を使い分けている。

**自分の理解：**

メモは「どんどん増えていくノートのページ」のようなもので、ちゃんと整理して管理する必要があるので SwiftData が向いている。

ユーザー名や設定は「机の上に貼ってある付箋」のようなもので、少なくて単純なので AppStorage で十分だと理解した。

データの大きさや役割によって保存方法を分けているのがポイントだと思う。

### Q3

**質問：**

Preview の inMemory: true は何を意味していますか？実際の保存と何が違うのですか？

**AIの回答の要点：**

inMemory: true はデータをメモリ上だけに保存する設定。

アプリや Preview を終了するとデータは消える。

通常の .modelContainer(for:) はディスクに保存するため再起動しても残る。

**自分の理解：**

inMemory は「机の上に一時的に置いたメモ」のようなもので、アプリを閉じると片付けられてしまう。

実際の保存は「引き出しにしまう」ようなもので、再起動しても残る。

Preview は確認用なのでこの一時保存が使われていると理解した。
